# 0001 — 실험 계획 확정 & 환경 준비

## 무엇을 했나
- 실험 방향 확정: STT 없이 `오디오 → log-mel → CNN`으로 **음성 내 전화번호 형식 숫자열 존재 여부** 탐지(feasibility test). 일반 PII/문맥 판단/STT 대체는 범위 밖.
- `plan.md`를 3차에 걸쳐 개정:
  - 1차(`rebuttal.md` 반영): confound(길이·발음스타일·숫자유무·템플릿·padding) 통제를 설계 중심으로 승격, baseline/평가셋/split/지표 보강, 결론 톤 하향.
  - 2차(최종판단 반영): 탐지 대상을 "전화번호 형식 존재"로 재정의, "예시/부정 문맥 전화번호"는 negative가 아니라 **positive**로(문맥 판단은 후단 몫). easy:hard = 7:3 확정.
  - 3차(`rebuttal2_sec.md` + 찬성/반대 서브에이전트 종합): **하이브리드 윈도/집계**(대칭 random-crop 5s + eval sliding-window max) 채택, **speaker-disjoint 미적용**(화자 2~3명 → 통제 불가 confound로 명시), **Stress-5:5 평가셋** 추가, 학습 설정·결과 해석 매트릭스 흡수. 윈도 ablation·정식 벤치마크·RF·MIL 타임스탬프는 v1 이후로 defer.

## 왜
- 합성 TTS 데이터 특성상 "PII 탐지"가 아니라 "artifact 탐지"가 될 위험이 커서, 결론을 방어 가능한 범위로 좁히고 통제 실험을 설계의 중심에 둠.

## 환경 (준비 완료)
- conda env `audio-pii` (Python 3.11)
- H100 NVL × 4, CUDA 13.0
- torch 2.12.0+cu130, torchvision 0.27.0+cu130, librosa 0.11.0, timm 1.0.27, edge-tts 7.2.8, ffmpeg 4.4.2
- ConvNeXt-Tiny(28.6M) 가중치 사전 다운로드 완료
- **주의**: 데이터 생성(edge-tts)은 GPU 미사용(네트워크/CPU 바운드). GPU는 이후 학습/추론 단계에서 사용.
