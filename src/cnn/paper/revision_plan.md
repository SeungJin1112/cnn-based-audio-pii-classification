### A-2. 그림/표 페이지 이탈 (피드백 2)
**문제**: 모든 float가 `[t]`로만 지정되어(L154, 186, 225, 264, 272, 298, 320, 342, 368, 384, 404) 뒤로 밀리고, 마지막 그림이 참고문헌 페이지까지 흘러가 "참고문헌 1 뒤에 그림" 상태가 됨. 10페이지 분량에 표 6 + 그림 5 = float 11개라 기본 float 파라미터로는 흡수 불가.

**조치** (3단계, 위에서부터 적용하고 남으면 다음 단계):
1. 프리앰블에 float 제어 추가
   ```latex
   \usepackage{float}
   \usepackage[section]{placeins}   % 절 경계를 float가 못 넘게
   \renewcommand{\topfraction}{0.9}
   \renewcommand{\bottomfraction}{0.7}
   \renewcommand{\textfraction}{0.1}
   \renewcommand{\floatpagefraction}{0.75}
   \setcounter{topnumber}{2}\setcounter{totalnumber}{3}
   ```
2. 배치 옵션을 `[t]` → `[!htbp]`로 일괄 변경, 각 float를 **참조 문단 바로 다음**으로 이동 (현재도 대체로 그렇지만 tab:dataset(L154)은 3.2절 통제 설명 중간에 끼어 있으므로 3.2절 끝으로 이동)
3. 그래도 밀리는 float(주로 fig:precision, tab:vs)는 `[H]`로 고정하거나 그림 폭 축소(`0.92\linewidth`→`0.8`, `0.62`→`0.55`)로 페이지 흡수
4. 참고문헌 앞에 `\FloatBarrier` 삽입 → 참고문헌 뒤로 그림이 넘어가는 것 원천 차단
5. 컴파일 후 PDF 육안 확인 (xelatex → bibtex → xelatex ×2)

### A-3. refs.bib [4] Microsoft 항목 (피드백 3)
**문제**: `refs.bib` L43-49 `@misc{azurepii}`의 `author={{Microsoft}}` + `plain` 스타일 → "Microsoft. Conversation PII redaction overview. ..." 로 회사명 뒤에 마침표가 붙어 인명처럼 보임.

**조치**: `@misc` → `@manual`로 바꾸고 저자를 `organization`으로 이동.
```bibtex
@manual{azurepii,
  title        = {Conversation {PII} Detection and Redaction},
  organization = {Microsoft},
  note         = {Azure AI Language documentation. \url{...}},
  year         = {2024}
}
```
→ "Conversation PII Detection and Redaction. Microsoft, 2024." 로 자연스럽게 출력.
**추가 점검**: `plain`은 저자 알파벳 정렬이므로 번호가 인용 순서와 무관. 인용 순서 번호를 원하면 `\bibliographystyle{unsrt}`로 변경 (피드백 2의 "참고논문 1", "참고논문 4" 지칭과도 일치시키기 쉬움). → **사용자 확인 필요 항목**

## B. 서술 스타일: 개조식 → 문장 서술 (피드백 4, 5)

### B-1. 서론 (L61~96)
**문제**: 1.2 문제제기(itemize 3개), 1.3 연구질문(RQ1~4 itemize), 1.4 기여(enumerate 5개) — 세 절이 연속 불릿이라 보고서 톤. 일반 논문 서론은 문단 서술이 표준.

**조치**: *내용은 지우지 않고* 문단으로 재작성 + 핵심 목록은 축약 유지.
- **1.2 문제 제기** → 3개 불릿을 3문단(또는 1문단 3문장 + 근거)으로 전환. 각 불릿의 수치(360 ms vs 0.344 ms, WER 중앙값 0인데 카드 재현율 0.852)는 문장 안에 그대로 유지.
- **1.3 연구 질문** → "본 연구는 다음 네 가지 질문에 답한다. 첫째, … 둘째, …" 형태의 한 문단으로 전환하고, **RQ1~RQ4 라벨은 괄호로 유지**(5장에서 RQ 번호로 참조하므로 라벨 자체는 필요). 예: "첫째, STT 없이 음향 특징만으로 PII 형식 숫자열을 탐지하는 것이 원리적으로 가능한가(RQ1)."
- **1.4 기여** → "본 연구의 기여는 다음과 같다."로 시작하는 1~2문단 서술. 5개 항목을 (i)~(v) 인라인 열거로 압축.
- 1.1~1.4 소제목(`\subsection`)도 서론에서는 과한 편 → **소제목 제거하고 서론을 연속 문단으로**, 대신 각 문단 첫 문장이 역할을 드러내게 작성 (배경 → 한계 → 착안 → 질문/기여). 상위 논문들의 서론 형태와 일치.

## C. 관련 연구 심화 (피드백 6, 7, 8)

### C-1. ASR-free / E2E SLU를 최근접 선행연구로 승격 (피드백 6)
**문제**: 현재 순서가 ①캐스케이드 → ②ASR-free SLU → ③KWS → ④음성 프라이버시 이고, ASR-free SLU 문단이 4문장뿐이라 "가장 가까운 관련 연구"로 보이지 않음. 지적대로 본 연구는 *ASR을 건너뛰고 음성에서 직접 상위 라벨을 예측*하는 E2E SLU의 한 사례이므로 이것이 핵심 계보.

**조치**:
1. 절 구조를 **2.1 문제 맥락(캐스케이드 PII 레닥션) → 2.2 가장 가까운 계보: ASR-free/E2E SLU → 2.3 인접 기술: KWS/구어 숫자 → 2.4 음성 프라이버시 → 2.5 연구 공백** 으로 재편하고, 2.2를 가장 길게(한 페이지 1/3 수준) 서술.
2. 2.2에 넣을 내용:
   - E2E SLU의 동기와 계보: ASR 오류 전파 회피, 파이프라인 단순화, 텍스트 병목 제거
   - 대표 접근 축: (a) ASR 사전학습 표현을 전이하는 방식(Lugosch et al.), (b) 음향 인코더 + CTC/보조손실 결합(Seo et al.), (c) 전체 개관(Serdyuk et al.)
   - **본 연구와의 위치 관계를 명시적으로 정리**: 동일한 점 = "텍스트를 거치지 않고 음성에서 직접 목표 라벨 산출". 다른 점 = ① 라벨 공간이 intent/slot 어휘가 아니라 *형식(format)* 이라는 비어휘적 상위 패턴, ② 목적이 최종 이해가 아니라 *프리필터*(고재현율·초저지연 운용점), ③ 평가가 정확도 경쟁이 아니라 *인공 단서 통제를 통한 타당성 검증*, ④ 모델 규모가 사전학습 음향 인코더(수천만~수억 파라미터)가 아니라 60K 파라미터 전용 CNN.
   - 왜 SLU 벤치마크(FSC 등)를 그대로 쓸 수 없는지: PII 형식 라벨과 hard-negative 통제를 갖춘 한국어 음성 데이터셋이 없어 자체 합성 필요 → 3장 데이터 설계로 자연스럽게 연결.

### C-2. KWS와의 **기술적** 차이 (피드백 7)
**문제**: 현재 L113-117은 "적용 범위가 다르다"만 말하고 기술적 차이가 없음.

**조치**: 적용 범위 + 아래 4가지 기술적 차이를 문단으로 서술.
| 축 | KWS | 본 연구 |
|---|---|---|
| 탐지 단위 | 고정 어휘(키워드/개별 숫자) — 짧은 앵커 음향 패턴 | 어휘 앵커가 없음. 판별 신호가 *숫자 낭독 구간의 길이·그룹 경계(휴지)·반복 리듬* 등 시퀀스 구조 |
| 입력 길이/집계 | 1초 내외 고정 창, 창 단위 posterior + smoothing | 5초 창 + hop 2.5초 sliding window, **클립 점수 = 창 점수 최댓값**(MIL식 집계) — 숫자열이 창을 걸쳐 있어도 탐지 |
| 판별 난이도 구조 | 음성적으로 다른 단어들 간 구분 | positive와 hard-negative가 **동일 어휘(같은 자릿수 발음 숫자)** 로 구성 → 어휘 식별로는 원리적으로 풀리지 않음 |
| 학습 데이터 | 고립 단어 코퍼스(Speech Commands 등) | 캐리어 문장에 삽입된 연속 발화, 템플릿 분리 분할 |
→ 결론 문장: "즉 KWS의 '무엇이 들렸는가'가 아니라 '들린 숫자들이 어떤 구조로 배열되었는가'를 푸는 문제이며, 이 때문에 KWS에서 표준인 어휘 단위 posterior 설계 대신 창 최댓값 집계와 hard-negative 통제가 필요하다."

### D-1. "읽기 방식 통제"의 의미 설명 (피드백 9)
**문제**: L144-145는 "자릿수 발음으로 읽게 했다"만 있고 *왜 그것이 통제인지*가 없음.

**조치**: 아래 논리를 예시와 함께 서술.
1. 한국어에서 숫자는 두 가지로 낭독된다 — **자릿수 읽기**("공일공 일이삼사": 0→공, 1→일 …)와 **수량 읽기**("삼만 오천 원", "이천이십육 년").
2. 자연스럽게 쓰면 전화번호·계좌번호는 자릿수 읽기가, 가격·날짜는 수량 읽기가 된다. 이 상태로 학습하면 모델은 PII 형식이 아니라 **낭독 스타일(음소 구성·운율)** 만으로 두 클래스를 분리할 수 있다 — 전형적인 지름길(shortcut) 단서.
3. 따라서 positive와 hard-negative **모두** 모든 숫자를 자릿수 발음으로 강제 변환했다.
   - 구현: `generate_qwen.py`의 `num_to_korean()`(구분자 단위 그룹화) / `digits_to_korean()`(문장 내 모든 숫자 치환)
   - 예시로 대조 제시: positive "제 전화번호는 **공일공 일팔이사 공사공구**입니다." vs hard-negative "오늘은 **이공이육**년 **삼**월 **이오**일입니다." (원문 "2026년 3월 25일"이 수량 읽기가 아니라 자릿수 읽기로 합성됨)
4. 결과적으로 두 클래스는 **음소 목록과 낭독 스타일이 동일**해지고, 남는 차이는 오직 "숫자열의 형식(연속 자릿수 길이와 그룹 경계 패턴)" 뿐이다.
→ 표 1 근처에 **실제 생성 문장 예시 표(클래스별 2~3개)** 신설 권장(표 2). 원문 텍스트/합성 텍스트/라벨 3열. 근거: `data_qwen/*/metadata.csv`의 `text` 컬럼.

### D-2. hard-negative의 역할 설명 (피드백 10)
**조치**: 아래 논리로 확장.
1. negative가 숫자 없는 일반 발화(easy)뿐이면, "숫자가 들리는가"라는 단순 규칙만으로 높은 정확도가 나온다 → 타당성 주장이 성립하지 않음.
2. 그래서 **숫자를 포함하되 PII가 아닌** 발화를 negative로 대량 투입: 날짜, 가격, 우편번호, 좌석, 버스번호, 생일, 송장(4+4), **주문번호(9~11자리)**, **제품 일련번호(4+4+4, 카드와 유사 길이)**, 수 세기 등 10개 카테고리(`HARD_CATS`). 자릿수 발음도 positive와 동일.
3. 특히 일련번호(12자리 3그룹)와 주문번호(9~11자리)는 **카드/전화 형식과 길이·그룹 구조가 의도적으로 충돌**하도록 설계했다 → 가장 어려운 반례.
4. 이로써 "숫자 존재" 단서는 두 클래스에서 상수가 되고, **hard-negative FPR이 곧 '형식을 배웠는가'의 직접 지표**가 된다(5.2절 FPR 0.006, 6.1절 카테고리별 분해).
5. 데이터 비율도 명시: v1 easy:hard = 7:3, v2 easy:hard = 1:1(450:450), positive:negative = 1:1.

### D-3. 데이터 생성 과정 전면 상세화 (피드백 11) — **VoiceDesign 질문 포함**
**문제**: 3.2~3.3절이 결론만 서술. "VoiceDesign으로 오디오를 만든 것인가?"라는 질문이 나온 이유는 3.3절(L169-174)이 화자 일관성 *결론*만 말하고 **파이프라인 전체를 서술하지 않기 때문**.

**정확한 사실관계(코드 근거)**:
- **v1**: `edge-tts` 3화자(`ko-KR-InJoonNeural`, `ko-KR-HyunsuMultilingualNeural`, `ko-KR-SunHiNeural`), 전화번호 단일 유형. positive 1,000 + hard-neg 300 + easy-neg 700(기존 `data/x` 재사용) = 2,000. positive 중 20%는 문맥변형("이건 예시입니다")이지만 형식은 들리므로 label=1. (`generate_pos.py`, `generate_neg_hard.py`, `config.py`)
- **v2**: `Qwen3-TTS-12Hz-1.7B` 2개 체크포인트 사용.
  - **VoiceDesign 체크포인트는 화자 참조 음성 1개를 만드는 데만** 사용: 14개 화자 각각에 대해 한국어 지시문(예: "20대 여성, 매우 높고 밝은 목소리, 빠른 말투")으로 고정 문장("안녕하세요, 오늘 하루도 좋은 하루 되시기 바랍니다.")을 1회 합성 → `voicebank/spkXX_ref.wav` (`qwen_voicebank.py: ROSTER`, `build_voicebank`)
  - **실제 데이터 1,800클립은 Base 체크포인트의 voice-clone으로 합성**: 위 참조 음성을 clone prompt로 만들어 모든 문장을 합성 (`VB.synthesize` → `generate_voice_clone`)
  - 화자 배정은 균등 순환(`sids[i % 14]`), 성별 7:7, 연령대 20~60 분포
  - positive 900(phone/rrn/account/card 각 225, 균등 순환), hard-neg 450, easy-neg 450 = 1,800 (`generate_qwen.py main()` 기본값, 실제 metadata.csv 행수와 일치: 900/450/450)
  - PII 값은 형식만 유효한 난수 생성: phone `010-XXXX-XXXX`, rrn `YYMMDD-Gxxxxxx`, account `3-3-6`, card `4-4-4-4` (실제 유효 번호 아님 — **윤리 관련 문장으로 명시할 것**)
  - 85% 확률로 캐리어 문장(앞/뒤 안내 문구) 결합 → 숫자열 위치가 문두/문중/문미로 분산
  - hard-neg 생성 시 우연히 전화번호 형식이 나오면 재생성(`PHONE_FMT` 가드, 최대 10회)
  - 출력: 16 kHz mono PCM16, seed 42 고정
- **화자 일관성 검증**: VoiceDesign을 발화마다 호출하면 화자 내 x-vector 코사인 거리 분산이 화자 간보다 커짐(within/between 0.61) → ref 1개 + clone 방식으로 within 0.0106, 비율 2.29로 개선. 로스터 전체 쌍 x-vector 거리로 화자 분리도 확인.

**조치**: 3.2절을 **"3.2 데이터 생성 파이프라인"**으로 재구성 — (1) 문장 생성(템플릿·값 생성기·캐리어), (2) 숫자 표기 정규화(자릿수 발음), (3) 음성 합성(v1 edge-tts / v2 VoiceDesign-ref + Base-clone), (4) 후처리(16 kHz mono, 노이즈 패딩)의 4단계 서술 + **파이프라인 그림 1개 신설 권장**(텍스트 템플릿 → 값 삽입 → 자릿수 변환 → TTS → wav). 3.3절은 (3)단계의 근거로 축약 연결.
**추가**: 표 1(데이터셋 구성)을 확장해 클래스별 클립 수, 화자 수, 평균 길이, PII 유형별 개수를 넣기. 근거: `metadata.csv`(v2 900/450/450), `config.py`(v1 1000/300/700).
**윤리 문단 신설**: 모든 음성은 TTS 합성이며 실제 개인의 음성·실제 PII 값이 아님을 3장 끝 또는 7장에 명시.

### D-4. 분할·학습 프로토콜 상세화 (피드백 12)
**문제**: 4.3~4.4절(L200-214)이 각 4~6줄. "어떻게 나누고 어떻게 학습했는지" 재현 불가.

**조치**: 4.3을 **"4.3 데이터 분할"**, 4.4를 **"4.4 학습 설정"**, 4.5를 **"4.5 평가 프로토콜"**로 분리하고 아래를 모두 명시(모두 코드에 존재하는 값).

**(a) 분할** (`splits.py: split_manifest`)
- 단위: 개별 클립이 아니라 **template_id 그룹** 단위로 배정 → 같은 문장 템플릿이 train/val/test에 동시에 등장하지 않음(template-disjoint). 템플릿 누수를 막지 않으면 모델이 캐리어 문장을 외울 수 있음.
- 라벨별로 70/15/15 목표를 따로 채움(label-stratified)
- 그룹을 평균 길이 순으로 정렬한 뒤 `cur/target`이 가장 작은 split에 순차 배정 → 세 분할이 길이 스펙트럼을 고르게 나눠 가짐(length-stratified). 길이 분포가 분할 간 어긋나면 길이 단서 통제(5.2절)가 무의미해지기 때문.
- test는 학습·하이퍼파라미터·모델 선택·임계값 튜닝 어디에도 사용하지 않음(임계값은 val에서만 튜닝)
- v1에서 Original 평가셋은 controlled-train에 포함된 파일을 제외해 누수 차단(`build_original_eval`) — 이 누수 진단 이력도 1~2문장으로 언급 가치 있음
- speaker-disjoint는 v1(3화자)에서는 적용 불가로 명시했고, **v2에서 LOSO로 별도 검증**(5.4절)함을 연결
- 실제 분할 크기(train/val/test n, 라벨 분포)를 표로 추가 — `runs/*/train.json`의 `split` 필드에서 추출

**(b) 학습** (`engine.py: train_model`, `train.py`)
- 옵티마이저 AdamW, lr `1e-4`, weight decay `1e-4`, batch size 32, 최대 epoch 50(v2 실험 40)
- CosineAnnealingLR(T_max=epochs), CrossEntropyLoss
- **에폭마다 val 클립 F1로 조기 종료(patience 8), 최고 val F1 시점 가중치 복원**
- 증강: 학습 시 5초 대칭 random-crop + SpecAugment(주파수 마스크 ≤8 bin, 시간 마스크 ≤16 frame, 각 1개)
- 시드 42/43/44 3회 반복 → 평균±표준편차 보고(표 3)
- 입력 정규화: log-mel per-sample 표준화(평균 0, 분산 1)
- 짧은 클립은 무음이 아니라 진폭 1e-3 노이즈로 우측 패딩(길이·무음 누수 차단) — 3장 통제와 교차 참조
- 하드웨어/런타임 1문장(GPU 종류, 학습 소요) 추가 권장

**(c) 평가**
- 클립 점수 = sliding window(5초, hop 2.5초, 마지막 창은 끝 정렬) 각 창의 P(positive) **최댓값**
- 5종 평가셋의 **구성 방식**을 명시: `controlled_main`(test 그대로), `length_matched`(positive 길이 히스토그램 10 bin에 맞춰 negative를 bin별 샘플링), `hard_negative_only`(positive+hard만), `stress_5_5`(negative 내부 easy:hard를 1:1 재가중 → positive:negative 균형이 깨지므로 ROC/PR-AUC와 per-class 지표 중심 해석), `original`(통제 이전 naive 데이터, 누수 제외 후)
- LOSO 절차(`speaker_pii_experiment.py: run_loso`): 화자 1명의 전 클립을 test로 고정, 나머지 13화자를 template-disjoint로 train/val 분할해 학습, val에서 임계값 튜닝 후 고정 0.5와 비교. 14폴드 반복.
- held-out-PII 절차(`run_heldpii`): 해당 유형 positive를 학습 풀에서 완전히 제거하고 나머지로 학습, test = 제외한 유형 positive + negative 샘플(2배). 해당 유형은 학습 중 한 번도 보지 않음.
- STT+NLP 비교(`stt/`): Whisper-large-v3 전사 → 규칙 기반 탐지 2종(형식만 / 형식+문맥 선행어). **동일 test 분할, n=331**에 적용.

## 해석을 강화·정정한 것

- **§5.4 LOSO 재해석(가장 큰 변화).** v1의 F1 0.616±0.280은 판별 실패가 아니라 **임계값 실패**였다. 폴드별 ROC-AUC는 0.971–0.999(**0.992±0.008**)이고, F1이 무너진 폴드(InJoon, recall 0.068–0.175)도 순위 성능은 온전하다. 즉 형식 신호는 미학습 화자에게도 일반화되며 개선된 것은 임계값의 화자 간 이식성이다. 또한 v1→v2는 화자 수 외에 TTS 엔진·PII 유형 수·에폭·시드 수가 모두 달라 교락이 있음을 명시.
- **§5.2에 미사용 증거 추가.** 통제 이전(`original`) 데이터에서는 **duration-only만으로 F1 0.956 / ROC-AUC 0.989**가 나온다(통제 후 0.633 / 0.701). 통제 설계의 필요성을 가장 직접적으로 증명하는 수치인데 초안에 없었다.
- **§5.3 근거 등급 구분.** 경량 CNN 우위의 4개 원인 중 실험으로 관측된 것은 (1) 대형 모델의 시드 불안정뿐이고 (2)(3)(4)는 해석적 가설임을 명시. 백본에 하이퍼파라미터 탐색·계층 동결·차등 학습률을 적용하지 않았다는 공정성 조건도 공개.
- **§6.1 v1 0.006 대 v2 0.54의 대비 완화.** 0.006은 hard-neg 192개 중 오탐 1건이고, v2 값은 충돌 난이도가 높은 3개 카테고리에 치우친 표본에서 나온 값이므로 배수로 읽지 말 것.
- **§5.5 held-out F1 설명 보강.** recall과 F1의 대상 집합이 다르고, 1:2 클래스 비율과 negative 누수가 함께 작용한다는 세 요인으로 분해.

## 미사용 결과를 꺼내 강화한 것 (전부 기존 산출물)

- `hard_negative_only`에서 CNN 정밀도 0.998·ROC 0.9992·PR-AUC 0.9997(다섯 평가셋 중 최고), 같은 셋에서 duration-only는 ROC **0.394**(우연 이하). length_matched에서 duration-only가 hard-negative의 90.7%를 오판하는 동안 CNN 오탐 0건.
- 통제 이전(`original`) 데이터에서 **duration-only(ROC 0.989)가 60K CNN(0.968)보다 높음** → 통제 설계가 방법론적 기여임을 보이는 최강 대비. acoustic-LR는 통제 전후 0.876↔0.878로 불변 → 제거된 것이 정확히 길이 축.

- v2 LOSO를 중앙값으로 재서술: F1 중앙값 0.904(9폴드 ≥0.87), 재현율 중앙값 0.977(5폴드 1.000), 튜닝 임계값이 0.25–0.55로 수렴.

## 적대적 검증에서 되돌린 것 (강화가 과했던 지점)

무결성 감사 결과 **거짓 1건, 과잉주장 7건**이 확인되어 전부 수정했다.

1. **(거짓) §4.7 "negative 쪽 비용은 별도로 측정하지 않고"** — 실제로는 측정했으나 누수로 무효인 것을 "미측정"으로 바꿔 쓴 것. 누수 사실을 한 문장으로 복원하고 recall만 보고한다는 근거로 재작성.
2. **초록 ROC-AUC "0.99 이상"** — 실측 최솟값 0.9709. 본문(0.971)과 모순되어 0.97로 정정.
3. **초록에서 정밀도 약점 소거** — v1 조건의 0.998만 남고 v2의 0.708/FPR 0.542가 사라져 있었음. 오탐률 0.42–0.54와 정밀도 과제를 초록에 복원.
4. **캐리어 논증의 "부호가 반대" 근거 삭제** — 캐리어는 카테고리와 무관하게 i.i.d. Bernoulli(0.85)로 부여되므로 카테고리별 비율 차이는 표집 잡음(전부 0.85±1.3SE). n=3 상관을 반증 근거로 쓴 것은 무효. 결정론적 규칙 기각으로 범위를 좁히고, 부분적 단서 가능성은 직접 검정이 필요함을 명시.
5. **τ=0.7 운용점에서 재현율 누락** — 정밀도 1.000·오탐 0·62% 절감만 적고 **재현율 0.728(PII 27% 누락)**을 빼놓았음. "세 시드 모두 62%"도 거짓(시드 43은 58.4%). 재현율을 명시하고 실사용 구간을 저임계값 쪽으로 한정.
6. **τ=0.8 회복 예시** — test 분포를 보고 사후에 고른 임계값이고, 같은 τ에서 InJoon 폴드는 F1 0.006–0.074로 붕괴. "세 화자를 동시에 만족시키는 단일 임계값이 없다"는 사실로 대체(v2 결과의 의미가 오히려 선명해짐).
7. **"실통화에서 격차가 더 벌어질 수 있다"** — 양방향 유보를 자기 유리 단방향으로 바꿨던 것. CNN도 함께 열화하므로 방향을 예단할 수 없다로 복원.
8. **보정 결과의 "긍정적인 사실"** — ECE 0.135는 절대적으로 낮지 않음. "보정 실패의 성격"으로 되돌리되 운용상 함의(보정 단계 불필요)는 유지.
9. **"네 겹의 통제"** — 실험으로 확인된 것은 둘(길이·숫자존재)이고 둘은 설계 통제. 결론(§8)의 "두 통제"와 모순되어 정정, 표 1 셀도 수정.
10. **출처 명세 누락** — 표 7 오른쪽 열과 보정 분석의 실행 귀속이 빠져 있었음. 세 실행에서 유형별 재현율이 0.865–0.962로 변동한다는 사실도 함께 공개.

# 5차: 2차 피드백(feedback2.txt) 반영 — 실험 재실행 + 재프레이밍 (2026-08-11)

2차 피드백은 상위 6개 항목이 전부 "새 실험"이었다. 전부 실행했고, 그 결과 논문의 중심 주장이
바뀌었다. 아래는 항목별 처리와 실제 산출 수치다. 코드는 `src/cnn/rev2/`, 산출물은
`src/cnn/rev2/out/`에 있다.

## 0. 실행 환경

원 실험에 쓰인 conda env `audio-pii`는 남아 있지 않아 `/data/hye0n/paper/venv`에 동등한 스택을
새로 구성했다(torch 2.9.1+cu128, torchvision 0.24.1, librosa 0.9.1, numpy 1.26.4,
scikit-learn 1.8.0). 파이프라인 무결성은 **원 논문 분할의 정확한 재현**으로 확인했다 —
`drop_outliers=False`로 돌리면 v2 test가 331개(positive 189 / hard 142), hard-negative
카테고리가 {수 세기 52, 주문번호 45, 좌석번호 45}로 논문 표와 완전히 일치한다.

## 1. 결정 함수의 특정 — 논문의 성격이 바뀐 지점

피드백은 "모델이 학습한 건 PII 형식이 아니라 긴 자릿수 연쇄"라고 지적하며 자릿수 길이 대 점수
곡선을 요구했다. 두 방향으로 측정했다.

**(a) 자릿수 구조 복원.** 생성 규칙(`generate_qwen.py`)에서 각 클립의 자릿수 그룹 구조를
정규식으로 100% 복원했다(실패 0건). positive는 전화 3-4-4(11자리), 계좌 3-3-6(12), 주민
6-7(13), 카드 4-4-4-4(16)이고, hard-negative는 주문번호 연속 10, 제품 일련번호 4-4-4(12) 등이다.

**(b) 카테고리별 미학습 오탐률(held-out-category).** 열 개 hard-negative 카테고리를 하나씩
학습에서 완전히 제외하고 그 카테고리 오탐률을 측정하는 절차를 신설했다(시드 3회, 30 run).

| 카테고리 | 구조 | 총 자릿수 | 미학습 FPR |
|---|---|---|---|
| 수 세기 | — | 0 | 0.397±0.036 |
| 버스번호 | 3 | 3 | 0.030±0.010 |
| 좌석번호 | 2-2 | 3 | 0.061±0.028 |
| 생일 | 1-2 | 3 | 0.113±0.051 |
| 가격 | 5 | 5 | 0.078±0.011 |
| 우편번호 | 5 | 5 | 0.114±0.011 |
| 날짜 | 4-1-2 | 7 | 0.225±0.084 |
| 송장번호 | 4-4 | 8 | 0.453±0.064 |
| 주문번호 | 10 | 10 | 0.622±0.096 |
| **제품 일련번호** | **4-4-4** | **12** | **0.947±0.041** |

**결론은 피드백의 가설을 확인하면서 동시에 수정한다.** 결정 변수는 피드백이 추정한 "최장 연속
자릿수 런"이 아니라 **"자릿수로 낭독된 총 자릿수"**다. 결정적 증거는 제품 일련번호(최장 런 4,
총 12자리, FPR 0.947)가 주문번호(최장 런 10, 총 10자리, FPR 0.622)보다 높다는 것이다.
스피어만 상관은 총 자릿수 ρ=0.936(수 세기 제외), 최장 런 ρ=0.496.

또한 v2 평가셋에서 **"총 자릿수" 단독의 라벨 예측 AUC가 1.000인데 CNN은 0.938**이다. 즉 CNN은
자릿수 총량 임계 규칙을 근사하되 그보다 못하며, 이 조건에서 형식을 추가로 쓴다는 증거는 없다.

논문은 이에 맞춰 §5.3 「결정 함수의 특정」을 신설하고, RQ2를 "형식을 학습하는가"에서 "결정
함수는 무엇의 함수인가"로 바꿨다. 초록·결론도 "상한을 측정한 논문"으로 재구성했다.

## 2. 실험 위생 — 결정성 고정 + 3시드

`torch.use_deterministic_algorithms` + cuDNN 결정성 + cuBLAS 워크스페이스 + DataLoader
생성기·워커 시드를 모두 고정했다. **동일 시드 2회 재학습에서 클립별 확률이 비트 단위로
일치**(max|Δp| = 0, n=336)함을 확인했다. 분할 시드는 42로 고정하고 학습 시드만 42/43/44로
바꾸므로 ±는 순수 학습 분산이다.

부수적으로 **655초 오염 클립 2개가 결과에 실제로 영향을 주고 있었음**을 발견했다. 하나가
좌석번호 카테고리에 속해 그 카테고리 평균 길이를 부풀렸고, 분할이 길이 오름차순 배정이라
평가셋 카테고리 구성 자체가 바뀌고 있었다. 제거 시 test hard-negative가 {수 세기, 주문번호,
좌석번호} → {수 세기, 생일, 송장번호}로 통째로 바뀐다. 그 결과 hard-negative FPR이
0.566±0.041(제거 전) → 0.329±0.034(제거 후)로 0.24 벌어진다. 이 사실을 §4.4·§4.3에 명시하고,
**단일 분할 FPR을 주 지표에서 내리고 카테고리별 미학습 FPR로 대체**했다.

주요 v2 수치(3시드): F1 0.859±0.011, 재현율 0.945±0.019, 정밀도 0.787±0.016,
ROC-AUC 0.938±0.006, hard-neg FPR 0.329±0.034. LOSO 14폴드×3시드: F1 0.871±0.085,
ROC-AUC 0.969±0.021, 튜닝 임계값 0.35–0.50. held-out-PII: 주민 0.919±0.008, 카드
0.902±0.010, 계좌 0.893±0.038.

**보정 분석의 결함도 발견해 고쳤다.** 기존 코드가 온도/Platt를 test에서 적합하고 있었다.
검증 분할에서 적합하도록 바로잡은 결과 ECE 0.098±0.012, 온도(T=0.67) 적용 후 0.097, Platt
적용 후 0.110으로 **"사후 보정의 실익 없음"이라는 논문의 결론 자체는 유지**된다.

## 3. 템플릿 부트스트랩 — 지배적 불확실성 축

피드백 지적대로 ±(시드)는 잘못된 축이었다. 템플릿 그룹 단위 부트스트랩(2,000회) 결과
F1 95% 구간 [0.519, 0.960], 정밀도 [0.363, 0.967], hard-neg FPR [0.167, 0.466]로
**시드 표준편차보다 한 자릿수 크다.** §6.1과 §7에 명시했다.

## 4. 캐리어 confound

클립별 점수를 보존해 조건부 오탐률을 직접 측정했다.

| 집단 | n | FPR | 평균 점수 |
|---|---|---|---|
| hard-neg, 캐리어 있음 | 130 | 0.372±0.047 | 0.400 |
| hard-neg, 캐리어 없음 | 17 | **0.000** | 0.149 |

"캐리어가 들리면 negative" 지름길은 **부호가 반대로 기각**된다(세 카테고리 안에서도 동일:
생일 0.183 대 0.000, 수 세기 0.512 대 0.000, 송장 0.474 대 0.000).

다만 이 측정이 **다른 잔여 단서를 드러냈다.** hard-negative 내부에서 클립 길이와 점수의
상관이 ρ=0.482(총 자릿수는 0.134)다. 5초 윈도보다 짧은 클립은 노이즈 패딩을 해도 윈도 안에서
음성이 차지하는 비율로 길이를 노출한다. 즉 §3.3의 노이즈 패딩은 길이 단서를 완전히 제거하지
못한다. 클래스 간 길이는 맞춰져 있어 주 결론에는 영향이 없으나 §3.2·§7에 명시했다.

## 5. 무학습 시간구조 기준선

온셋 검출 → 등간격 음절 연쇄 → 임계값. 기준선을 불리하게 잡지 않기 위해 최장 연쇄 길이 /
등간격 연쇄 온셋 총합 / 전체 온셋 수 세 통계를 두고 검증 분할에서만 선택했다.

- v1: F1 0.768, ROC-AUC 0.804 (최장 런 변형은 0.687/0.546, 전체 온셋 수는 0.781/0.800)
- v2: F1 0.778, ROC-AUC 0.734

**과제의 상당 부분이 학습 없는 규칙으로 설명되지만** CNN은 ROC-AUC에서 0.19–0.20의 폭을
남긴다. 표 5에 기준선 행을 추가하고 §5.1에 해석을 넣었다.

## 6. Whisper 다중 설정 — "구조적 취약성" 검정 통과

기본(greedy) / 숫자 형식 예시 프롬프트 / 빔 서치(5) / 빔+프롬프트 네 설정에서 측정.
**16자리 카드번호 재현율이 0.864 / 0.802 / 0.852 / 0.815로 네 설정 모두 무너진다**(주민 13자리는
네 설정 모두 1.000). 프롬프트가 오히려 가장 낮다. 같은 인스턴스에서 CNN은 세 시드 전부 1.000.
"설정 미조정이 아니라 구조적"이라는 논문 주장이 유지된다.

## 7. 협대역·코덱·잡음 열화

| 조건 | F1 | Recall | ROC-AUC |
|---|---|---|---|
| clean 16 kHz | 0.859±0.011 | 0.945±0.019 | 0.938±0.006 |
| 8 kHz 왕복 | 0.849±0.016 | 0.910±0.030 | 0.920±0.007 |
| + G.711 μ-law | 0.831±0.013 | 0.910±0.031 | 0.914±0.009 |
| 잡음 SNR 20 dB | 0.586±0.109 | 0.474±0.137 | 0.745±0.020 |
| 잡음 SNR 10 dB | 0.653±0.110 | 0.647±0.191 | 0.726±0.031 |

**대역·코덱은 거의 무해하고 잡음이 병목이다.** 잡음 하에서 정밀도는 오히려 오르므로(0.787 →
0.841) 실패의 성격은 판별 불능이 아니라 운용점 이동이다. SNR 20 dB가 10 dB보다 나쁜
비단조성은 관찰 사실로만 보고했다. §5.8 신설.

## 8. 비용 모형

ρ = pR + (1-p)(qF_h + (1-q)F_e), 순절감 = (1-ρ)c_s - c_f - (1-R)p·c_m.
측정값 R=0.945, F_h=0.329, F_e=0.020(v1 test에서 시드별 역산), c_f/c_s=5e-3.
p=0.05, q=0.3이면 호출률 0.154(84% 절감), 손익분기 c_m/c_s=308. §6.4 신설(표 포함).
"숫자 포함 트래픽에서 16%"는 최악 조건의 하한임을 명시했다.

## 9. 화자 일관성 독립 재검증

ECAPA-TDNN(VoxCeleb)으로 재측정: 화자 내 0.242, 화자 간 0.506, between/within **2.09**
(Base 모델 자체 임베딩 기준 2.29와 사실상 동일). 다만 최근접 쌍 spk05–spk07 거리 0.179가
화자 내 평균보다 작아 두 화자는 독립 검증 모델 기준으로 충분히 분리되지 않는다. §3.4에 반영,
인용도 x-vector에서 실제 사용한 ECAPA로 교체.

## 10. 그 밖에 반영한 지적

- 표 4의 v1 train/val 클래스 분해를 재계산해 채움(train 665/180/498, val 162/58/106).
- 초록 재구성: v1 LOSO 0.992 삭제, "약 1,000배" 서론으로 강등 후 비용 모형으로 연결,
  어려운 조건 수치를 앞으로.
- PR-AUC 0.998 대 0.960±0.050을 "유의하다고 주장할 수 없음"으로 완화. "460배" 표현 제거.
- §6.3 프라이버시를 데이터 최소화 논거로 정확히 좁힘(PII 발화는 전부 전사됨을 명시).
- §7에 "합성 분포 자체가 지름길인 층위"를 추가 — 결정 변수가 등간격 음절 개수이므로 TTS의
  규칙적 운율이 하필 그 신호를 부풀린다는 점을 명시하고 소규모 실녹음을 최우선 과제로 둠.
- 제품 일련번호가 평가에서 빠지는 문제는 held-out-category 절차로 해소.


## 1-보강. 통제 자극 실험 (자릿수 곡선)

카테고리별 실험은 관측 자료라 어휘·문형이 함께 변한다. 같은 TTS 백엔드·같은 14화자로 PII 의미가
전혀 없는 순수 난수 자릿수열 1,280개를 합성해 통제 자극으로 썼다. 축은 (A) 연속 4/6/8/10/12/14/16자리
×100, (B) 총 자릿수 8/12/16을 4자리 그룹으로 끊은 것 ×100, (C) 문틀 없이 숫자만 ×40. 문틀은
"번호는 {v}입니다."로 고정. 채점은 v2 세 시드 평균.

| 총 자릿수 | 4 | 6 | 8 | 10 | 12 | 14 | 16 |
|---|---|---|---|---|---|---|---|
| 연속·문장 | 0.00 | 0.00 | 0.03 | 0.26 | 0.65 | 0.89 | 0.95 |
| 4자리 그룹 | — | — | 0.05 | — | 0.54 | — | 0.97 |
| 맨숫자 | 0.00 | 0.00 | 0.00 | 0.00 | 0.13 | 0.45 | 0.63 |

- **시그모이드 확인.** 로지스틱 반포화점 **11.3자리**. PII 유형이 11–16자리에 몰려 있으므로 결정
  경계가 정확히 PII 구간 하단에 놓였다.
- **그룹 구조 무영향.** 총 자릿수를 맞추고 4-4-4-4로 끊어도 곡선이 겹친다(반포화점 11.3 대 11.8).
- **길이와 자릿수는 완전히 분리되지 않는다.** 문틀을 없애면 곡선이 통째로 오른쪽으로 밀려
  반포화점이 14.8자리가 된다(문틀 단어가 자릿수 약 3.5개분의 증거로 작용). 길이가 비슷하고
  자릿수만 다른 쌍에서는 자릿수의 독립 기여가 보이지만(맨숫자 14자리 3.14초 0.450 대 문장
  10자리 3.24초 0.260), 표준화 로지스틱 계수는 자릿수 1.71 / 길이 2.17로 길이가 약간 크다.

→ 논문의 최종 진술은 "모델은 자릿수 낭독의 분량과 발화 전체의 분량을 함께 재며, 그 가운데 그룹
구조만은 쓰지 않는다"로 확정했다. 카테고리 실험에서도 길이(ρ=0.895)와 총 자릿수(ρ=0.916)가
공선적임을 함께 보고한다.

| 모델 | 1e-5 | 3e-5 | 1e-4 |
|---|---|---|---|
| simple_cnn | 0.628±0.048 | 0.756±0.049 | **0.952±0.012** |
| mobilenet_v3_small | 0.622±0.103 | 0.776±0.003 | **0.784±0.005** |

| convnext_tiny | 0.776±0.067 | 0.815±0.072 | **0.852±0.116** |

**네 모델 모두 1e-4가 최적**이다. 사전학습 백본에 1e-4가 과대했다는 가설은 기각된다. ConvNeXt의
시드 간 불안정도 학습률을 낮추면 표준편차는 줄지만(±0.116 → ±0.072 → ±0.067) 평균이 함께

설정에서"에서 **"각 모델에 가장 유리한 학습률을 고른 뒤에도"**로 강화하고, 기여 (v)를 복원했다.
다만 비교군이 전부 ImageNet 백본이라는 한계는 그대로 남겨 두었다(PANNs/AST 비교는 향후 과제).

## 6-보강. Whisper WER 재측정

30초 청크 파이프라인 대신 모델을 직접 호출하니 일반 발화 449개에서 WER 중앙값 0, **평균 0.079**,
완전일치 80.8%, **환각 0건**이었다. 논문이 보고하던 평균 WER 0.722와 환각 1건은 전사 자체의
한계가 아니라 장문 디코딩 절차의 산물이었음이 드러나, §5.7을 그에 맞게 정정했다. 네 설정 모두

## 7-보강. 같은 열화에서 STT+NLP는 무너지지 않는다 (가장 중요한 추가 발견)

열화 클립을 STT+NLP 경로에도 그대로 적용했다.

| 조건 | CNN F1 / recall | STT+NLP F1 / recall |
|---|---|---|
| clean | 0.859 / 0.945 | 0.964 / 0.931 |
| 8 kHz 왕복 | 0.849 / 0.910 | 0.947 / 0.899 |
| + G.711 | 0.831 / 0.910 | 0.956 / 0.915 |
| 잡음 SNR 20 dB | **0.586 / 0.474** | **0.964 / 0.931** |
| 잡음 SNR 10 dB | **0.653 / 0.647** | **0.964 / 0.931** |
| G.711 + SNR 20 dB | 0.526 / 0.402 | 0.967 / 0.937 |
| G.711 + SNR 10 dB | 0.630 / 0.612 | 0.953 / 0.910 |

대역·코덱에서는 두 경로가 함께 조금씩 내려가지만, **가산 잡음에서는 CNN만 무너지고 Whisper는
사실상 무손실**이다. 논문이 유지하던 "실통화에서는 CNN도 ASR도 함께 열화하므로 격차의 방향을
예단할 수 없다"는 유보가 측정으로 해소되었고, 방향은 음향 프리필터에 불리하다.

이에 따라 §6.2의 2단계 파이프라인 제안에 **명시적 전제**를 붙였다 — 입력 SNR이 충분히 높거나
프리필터가 잡음 증강 학습된 경우에만 성립하며, 잡음이 심한 구간에서는 프리필터를 우회하고
전량 전사하는 분기를 두는 편이 안전하다. 초록·§7·결론도 같은 취지로 고쳤다. (단, 여기 쓴 잡음은
정상 백색잡음이므로 실제 배경 대화·음악 등 비정상 잡음까지 일반화되지는 않는다고 명시했다.)

## 4-보강. v3 재합성 — "positive에도 캐리어를 붙여라"는 제안의 검증 결과

피드백의 "근본 해결"(positive에도 동일 확률로 캐리어 부착)을 실제로 수행했다. positive 900개를
캐리어 85% 확률로 전부 재합성(v3)하고 기존 hard/easy와 결합해 3시드로 학습했다.

| | 캐리어율 (pos / hard) | 길이 중앙값 (pos / hard) | F1 | hard-neg FPR |
|---|---|---|---|---|
| v2 | 0.000 / 0.871 | 4.56s / 4.64s | 0.859±0.011 | 0.329±0.034 |
| v3 | **0.870 / 0.871** | **6.16s** / 4.64s | **0.999±0.001** | **0.002±0.003** |

캐리어 confound는 실제로 사라졌지만(0.870 대 0.871), **같은 조작이 길이 정렬을 깨뜨려** positive가
1.6초 길어지고 과제가 붕괴한다(ROC-AUC 1.000, 재현율 1.000). v3의 캐리어 조건부 오탐률은
캐리어 있음 0.003 / 없음 0.000으로 차이가 사라지지만, 그 대가로 길이가 클래스를 거의 완전히
분리한다.

결론: 캐리어를 hard-negative에만 붙인 v2 설계는 회피 가능한 결함이 아니라 **두 confound 사이의
교환**이다. 캐리어는 길이를 맞추기 위해 존재하고, 길이 통제가 훨씬 중요하다. 논문은 모든 성능
수치를 길이가 맞추어진 v2에서 보고하고, v3는 "길이 통제가 풀리면 성능이 어디까지 부푸는가"를
보여주는 상한 참조점으로만 쓴다. §3.2와 §5.2에 이 논증을 넣었다.

부수 발견: v3 합성 중 한 샤드가 TTS 반복 생성 루프에 걸려 멈췄다. v2의 655초 클립과 같은
현상이며, `gen_tts.py`에 길이 가드(20초 초과 시 최대 3회 재생성 후 절단)와 재개 기능을 추가해
해결했다. 이 병리가 재현 가능하다는 사실 자체가 §3.6 데이터 품질 서술의 근거가 된다.

## 중대 1 — 잡음 열화 결론이 구현 아티팩트였다 (가장 심각)

`degrade_eval.py`가 **대역 제한 이후에 전대역 백색잡음**을 주입하고 있었다. G.711을 거친
신호의 4–8 kHz 에너지는 실측 0인데, 공칭 SNR로 전대역 잡음을 넣으면 잡음 전력의 절반이
신호가 전혀 없는 대역에 떨어진다. 그 대역은 64채널 멜 필터뱅크의 절반을 차지한다.
**즉 표적 도메인(8 kHz 협대역 전화망)이 물리적으로 만들 수 없는 조건이었다.**

잡음을 전화 통과대역(300–3400 Hz)으로 제한하고 SNR을 대역 내 전력비로 재정의해 재측정:

| 조건 | 재현율(전대역) | 재현율(통과대역) |
|---|---|---|
| G.711 + SNR 20 dB | 0.402 | **0.933** |
| G.711 + SNR 10 dB | 0.612 | 0.746 |

**"가산 잡음이 프리필터를 무너뜨린다"는 5차 결론은 철회한다.** 통과대역 조건에서 무너지는
것은 재현율이 아니라 정밀도(hard-neg FPR 0.329→0.696)와 운용점 안정성(SNR 5 dB에서 시드별
재현율 0.000/1.000/1.000)이다. 프리필터에서 재현율 손실과 정밀도 손실은 비용이 전혀 다르므로,
정정된 결론은 훨씬 덜 치명적이다. 초록·§5.10·§6.2·§7·§8을 모두 재작성했다.

## 중대 2 — 잡음 완화 실험 부재 (게재 거부 최대 요인)

`rev2/noise_aug.py` 신설. 학습 데이터의 절반에 대역 제한·μ-law 근사·통과대역 잡음
(SNR 5–25 dB)을 확률적으로 섞어 3시드 재학습했다.

| 조건 | 기본 F1 | 증강 F1 |
|---|---|---|
| clean | 0.859±0.011 | 0.807±0.010 |
| 통과대역 20 dB | 0.754±0.015 | 0.757±0.003 |
| 통과대역 10 dB | 0.625±0.167 | **0.771±0.002** |
| 통과대역 5 dB | 0.492±0.348 | **0.776±0.024** |

**증강 학습이 SNR 전 구간에서 성능을 평평하게 만든다.** 시드 간 표준편차도 ±0.348 → ±0.024로
줄어 운용점 불안정이 해소된다. 대가는 깨끗한 조건의 F1 0.05다. 표 tab:degrade에 열을 추가하고
기여 (vi)를 이에 맞게 고쳤다.

## 중대 3 — "형식만으로 도달 가능한 상한"은 논리 오류였다

12자리 제품 일련번호(4-4-4)와 12자리 계좌번호(3-3-6)는 자릿수 총량이 같지만 **그룹 구조가
다르다**. 그룹 경계를 쓰는 모델이라면 가를 수 있으므로, 0.947은 *과제*의 상한이 아니라
*이 모델이 학습한 결정 축* 위의 상한이다. 모델의 한계를 과제의 한계로 승격시킨 오류였다.
초록·기여 (ii)·§6.1·결론 네 곳을 "현재 모델의 결정 축 위에서의 상한"으로 고치고, 남은 개선
방향(그룹 경계를 결정에 반영하는 표현 학습)을 명시했다.

## 중대 4 — v3 "두 confound 사이의 교환" 논증이 자기 데이터와 충돌했다

v3 안에 길이가 정확히 같은 두 집단이 있다: 캐리어 없는 positive(4.64초, n=57)와 캐리어 있는
hard-negative(4.64초, n=390). 이 둘의 판정률이 **1.000 대 0.003**이다. 길이가 맞춰진
조건에서도 완벽히 갈리므로 "v3 포화는 길이 정렬이 깨져서"라는 설명은 성립하지 않는다.

정정: v3에서 달라진 것은 **학습 시점에 캐리어가 클래스와 상관되는지 여부**뿐이고, 그 상관을
없애자 분리가 뚜렷해졌다. 즉 v2 난이도의 일부는 과제의 본질이 아니라 학습 데이터의 얽힘에서
왔으며, **캐리어를 positive에도 붙이라는 제안이 옳았다.** 다만 v3는 클래스 간 길이 정렬이
깨지고 평가 분할 구성도 달라져 v2와 직접 비교할 수 없으므로, 보수적인 v2를 주 보고 대상으로
유지하고 v3는 참조점으로 쓴다.

## 6차 추가 — 재검증에서 나온 2차 결함과 처리

수정본을 다시 3개 에이전트로 재심사한 결과 새 결함 10건과 미해소 3건이 나왔다. 중대만 정리한다.

1. **열화 캐시 오염 + 시드별 잡음 미분리.** `build_condition`이 파일 존재 여부만 보고 캐시해,
   (a) 코드 개정 이전에 만들어진 클립 1개가 잡음 없이 살아남았고, (b) 세 시드가 같은 잡음
   실현을 공유해 ±가 학습 분산만 담고 있었다. 캐시 키에 시드를 넣고 `out/degraded`를 전부
   재생성해 3시드 독립 실현으로 재측정했다. 결론은 유지되고 수치는 ≤0.02 이동했다
   (예: 통과대역 20 dB 재현율 0.933→0.931, 전대역 20 dB 0.402→0.418).

2. **증강 잡음이 평가 잡음과 동일 과정이었다.** `noise_aug.py` docstring이 "서로 다른 구현"이라
   적고 있었으나 통과대역 잡음 항은 대역·필터·잡음원·SNR 정의가 평가와 같고 학습 SNR 범위
   [5,25]가 평가점 {20,10,5}를 모두 포함한다. docstring을 정정하고, §5.10에 "이 회복치는
   정합 조건에서의 상한이며 처음 보는 잡음으로의 일반화가 아니다"를 명시했다. 근거로
   학습에 없던 전대역 잡음에서는 증강이 오히려 악화된다는 사실(F1 0.542→0.435)을 덧붙였다.

3. **v3 논증이 두 번째로 틀렸다.** 6차에서 "길이를 맞춘 하위집단에서도 갈린다"고 썼으나,
   그 두 집단은 총 자릿수가 12–13 대 0–8로 전혀 달라 자릿수와 교락되어 있었다. 게다가 인용한
   n=57/390은 3시드 풀링값이고 실제 분할값은 19/130이었다. **귀속을 포기하고**, v2와 v3가
   (i) 캐리어-클래스 상관, (ii) 클래스 간 길이 정렬, (iii) 평가 분할 구성 세 가지가 동시에
   다르다는 사실만 적은 뒤 v2를 주 보고 대상으로 유지했다.

4. **§5.3에 폐기된 옛 주장 잔존.** "길이 정렬이 깨진 v3에서는 성능이 곧바로 포화한다"를
   길이 민감성의 근거로 쓰고 있어 §5.2와 모순됐다. 삭제하고 hard-negative 내부 상관 0.482만 남겼다.

5. **§4.8 대 §5.6의 LOSO 실행 횟수 불일치**(14회 대 42회) — 42회로 통일.

6. **SNR 정의 비교 오류.** 전대역 SNR은 전체 전력, 통과대역 SNR은 대역 내 전력 기준이라
   "같은 공칭 SNR" 비교가 부정확했다. 통과대역 20 dB가 전체 전력 기준 약 24 dB에 해당함을
   명시하고, 4 dB 차이로는 0.418과 0.931의 간극이 설명되지 않음을 밝혔다.

7. **`\emph`가 렌더링되지 않았다.** 한글 이탤릭 폰트(UnBatang-Italic)가 없어 44곳의 강조가
   PDF에서 무효였다. `\renewcommand{\emph}[1]{\textbf{#1}}`로 굵게 처리했다.

8. **그림 재현 불가.** `make_figs2.py`의 `fig_degrade()`가 구버전 요약을 읽어, 재실행하면
   본문 캡션과 어긋나는 옛 그림으로 덮어썼다. 실제 사용한 생성 코드로 교체했다.

부수: 비용 모형의 F_e를 깨끗한 조건 값으로 쓴 점(낙관적 추정임을 명시, 3배 민감도 77 병기),
부트스트랩 "여섯 그룹" 단서를 초록·§6.1·§7 세 곳 모두에 반영, Whisper 지연 0.360 s의 출처

## 8차 — 순서 헤드 통제 실험 (§5.3 보강)

**동기.** 5.3절은 `simple_cnn` 의 결정 변수가 그룹 구조가 아니라 자릿수 낭독의 분량임을 보였다.
그러나 `simple_cnn` 의 헤드는 `AdaptiveAvgPool2d(1)` 이라 시간축 순서가 설계상 소멸한다.
따라서 "그룹 경계를 못 쓴다"가 표현의 한계인지 풀링의 산물인지 그 실험만으로는 가를 수 없었고,
논문은 네 곳에서 "그룹 경계를 반영하는 표현을 학습시키면 상한을 넘어설 수 있다"를 **근거 없이**
주장하고 있었다.

**설계.** 합성곱 몸통을 고정한 채 헤드만 바꾼 세 변형(`models/seq_heads.py`)을 같은 데이터·
같은 결정적 절차로 학습(시드 42/43/44). in-distribution 과 제품 일련번호 held-out-category,
그리고 통제 자극 채점까지 18회 학습 + 3회 채점.

| 모델 | 헤드 | 순서 | 스텝 | 파라미터 |
|---|---|---|---|---|
| `simple_cnn` | 균등 평균 | 무시 | 512 ms | 60,706 |
| `attn_cnn` | 학습된 가중 평균 | 무시 | 512 ms | 60,771 |
| `gru_cnn` | BiGRU + 가중 평균 | 인지 | 512 ms | 79,587 |
| `gru_cnn_hires` | BiGRU + 가중 평균 | 인지 | 128 ms | 79,587 |

**결과.**

| 모델 | F1 | hard-neg FPR | ROC-AUC | 일련번호 FPR | 반포화점 연속/그룹 |
|---|---|---|---|---|---|
| `simple_cnn` | 0.859±0.011 | 0.329±0.034 | 0.938 | 0.947±0.041 | 11.3 / 11.8 |
| `attn_cnn` | 0.915±0.003 | 0.150±0.036 | 0.971 | **0.687±0.034** | 11.5 / 11.7 |
| `gru_cnn` | **0.932±0.011** | **0.143±0.029** | **0.984** | 0.780±0.071 | 11.2 / 11.3 |
| `gru_cnn_hires` | 0.925±0.008 | 0.166±0.031 | 0.978 | 0.813±0.034 | 11.2 / 11.4 |

1. **그룹 구조는 여전히 안 쓰인다.** 반포화점 격차가 오히려 0.5 → 0.1자리로 **줄었다**.
   16자리 판정 비율도 연속 0.97 대 그룹 0.99 로 겹친다.
2. **그런데 성능은 크게 오른다.** v2-HN 에서는 총 자릿수만으로 라벨이 완벽히 분리되므로
   (ROC-AUC 1.000) 이 상승은 새 축이 아니라 **같은 축 위 근사의 정밀화**다. 자릿수 규칙까지의
   격차 중 74% 를 메웠다.
3. **개선의 원인은 순서가 아니다.** 치환 불변인 `attn_cnn` 이 파라미터 65개로 F1 0.915 를 내고,
   일련번호 오탐률은 순서를 보는 두 변형보다 **더 낮다**(0.687 대 0.780/0.813).
4. **학습 신호 부재도 아니다.** 학습 분할에 serial(4-4-4, 12자리, negative, n=50)과
   account(3-3-6, 11–12자리, positive, n=121)이 함께 있어 자릿수만으로는 못 가르는 쌍이
   직접 감독된다. 그런데도 어느 구조도 그룹 경계를 학습하지 않는다.

**논문 반영.** 표 5(`tab:seqhead`)와 §5.3 `\paragraph{풀링이 지운 것인가}` 를 추가하고,
근거 없던 주장 네 곳(국문 초록 / §6.1 / §8 결론 / §7 향후 과제)을 실측에 맞게 고쳤다.
"그룹 경계를 학습시키면 넘어설 수 있다" → "표현 구조를 바꾸는 것만으로는 열리지 않는다;
남은 레버는 문맥 결합과 그룹 구조만이 판별 단서가 되는 학습셋 설계다". 아울러 v2 헤드라인
0.859 가 접근법이 아니라 **헤드의 한계**였음을 명시하고, 주 모델 교체 재실행을 후속 과제로 넣었다.

**최종 상태**: 16쪽 2단, 표 11 / 그림 3, 컴파일 오류·overfull·미정의 인용 0건.

## 9차 — 결합 설계 실측: 캐스케이드 대 합집합 (§6.2 신설)

**동기.** 8차에서 음향 모델의 결정 변수가 자릿수 낭독의 분량임이 강건한 성질로 확인되면서,
이 모델을 "PII 후보 선별기"로 쓰는 캐스케이드의 전제가 무너졌다. 반면 5.6절의 유형별 재현율은
두 경로의 실패가 반대 방향임을 보인다(카드 16자리: 전사 0.864 대 음향 0.988). 그렇다면 이
상보성을 어떤 논리 연산으로 쓸지가 실제 설계 문제다.

**방법.** Whisper 전사가 `out/tx_{조건}_{설정}.csv` 에 이미 캐시되어 있어 GPU 없이 클립 단위
판정을 재구성할 수 있었다. `rev2/union_eval.py` 로 네 설계를 같은 인스턴스에서 비교했다
(캐스케이드 = 두 판정의 논리곱, 합집합 = 논리합). 추정이 아니라 **실측**이다.

**결과 (v2-HN, positive 189).**

| 조건 | 설계 | Recall | Precision | 놓친 PII |
|---|---|---|---|---|
| clean, `simple_cnn` τ=0.5 | STT 단독 | 0.931 | 1.000 | 13.0 |
| | 캐스케이드 | 0.877±0.019 | 1.000 | **23.3** |
| | 합집합 | **1.000±0.000** | 0.797±0.017 | **0.0** |
| clean, `gru_cnn` τ=0.9 | 캐스케이드 | 0.783±0.019 | 1.000 | 41.0 |
| | 합집합 | **0.993±0.002** | **0.979±0.008** | **1.3** |
| bp05, `simple_cnn` τ=0.5 | STT 단독 | 0.873 | 1.000 | 24.0 |
| | 음향 단독 | 0.667±0.471 | 0.389±0.275 | 63.0 |
| | 캐스케이드 | 0.582±0.412 | 0.667±0.471 | 79.0 |
| | 합집합 | **0.958±0.060** | 0.722±0.197 | **8.0** |

1. **캐스케이드는 재현율에서 STT 단독보다 나쁘다.** 놓친 PII 13.0 → 23.3건. 프리필터가 PII 일부를
   후단이 보기 전에 버리기 때문이며 임계값을 올릴수록 악화된다(τ=0.9에서 41.0건). 캐스케이드의
   이득은 검출이 아니라 **비용 절감뿐**이다.
2. **합집합은 놓친 PII를 거의 없앤다.** τ=0.9 순서 헤드로는 재현율 0.993 / 정밀도 0.979 로
   STT 단독(0.931 / 1.000)을 재현율에서 크게 앞서면서 정밀도는 0.021 만 내준다.
3. **합집합은 열화에 강건하다.** SNR 5 dB 에서 음향 단독은 재현율 0.667±0.471 로 시드에 따라
   붕괴하지만 합집합은 0.958±0.060 을 유지한다. 전사 경로가 받쳐 주므로 음향 경로의 불안정이
   최종 판정으로 전파되지 않는다. 캐스케이드는 반대로 실패를 증폭한다(놓침 79.0건).

**논문 반영.** §6.2 를 「결합 설계: 캐스케이드 대 합집합」으로 신설하고 표 11(`tab:combine`)을
추가, 기존 비용 모형은 §6.3 으로 분리했다. 음향 경로의 역할을 세 층으로 정리했다 —
(i) PII 분류기는 **성립하지 않음**, (ii) 비용 프리필터는 **조건부**(숫자 없는 발화가 많은
트래픽에서만), (iii) **재현율 안전망**이 가장 강하게 지지됨. 초록·기여 (iv)·결론의
"2단계 파이프라인" 서술도 이에 맞게 고쳤다.

**최종 상태**: 17쪽 2단, 표 12 / 그림 3, 컴파일 오류·overfull·미정의 인용 0건.

## 10차 — 프리필터 임계값 재분석과 F_e 실측

**계기.** "프리필터로 써도 별로냐"는 물음에 답하려면 재현율을 지킬 때 절감이 얼마나 남는지를
임계값의 함수로 재야 했다. 9차에서 낸 "캐스케이드는 STT 단독보다 나쁘다"가 **tau=0.5 하나만 보고
일반화한 것**이었음이 여기서 드러났다.

**F_e 실측.** 논문은 숫자 없는 발화의 오탐률을 v1에서 빌려온 0.020으로 쓰고 있었다. LOSO 폴드를
모으면 시드마다 easy-negative 449개 전부가 **학습에 쓰이지 않은 화자**의 클립으로 한 번씩
채점되므로 화자 수준에서 누수 없는 추정이 된다. 재보니 tau=0.5에서 **F_e=0.085**로 네 배였다.
(한계: 화자는 분리되나 easy-negative 문장 템플릿 12종은 학습에도 등장하므로 여전히 낙관적일 수 있다.)

**임계값 스윕** (콜센터형 p=0.05, q=0.30, 발화 1,000건당):

| tau | R | 절감률 | 놓친 PII | 손익분기 |
|---|---|---|---|---|
| 0.10 | **1.000** | 39.9% | **0.0** | — |
| 0.20 | 0.996 | 56.3% | 0.2 | 3,167 |
| 0.30 | 0.988 | 66.6% | 0.6 | 1,070 |
| 0.50 | 0.945 | 80.2% | 2.7 | 292 |
| 0.90 | 0.587 | 96.4% | 20.6 | 46 |

캐스케이드 재현율도 tau=0.1에서 0.931로 **STT 단독과 정확히 같다**(tau=0.5에서는 0.877).
즉 프리필터는 "재현율을 지키려면 절감을 포기하는" 장치가 아니며, 문제는 기본값 0.5였다.

**논문 반영.** 표 13(`tab:tau`) 신설, `tab:cost` 를 F_e=0.085로 전면 재계산, §6.2·초록·결론의
캐스케이드 서술을 임계값 조건부로 정정.

### 검증에서 나온 결함 (29건 제기 → 10건 통과, 전부 반영)

1. **[critical] 열화 조건 비용 문단이 폐기된 F_e=0.020으로 남아 있었다.** 같은 절의 표가
   0.198/292를 주는데 본문은 0.154/308을 출발점으로 썼다. 대입한 R=0.840, F_h=0.488도 구
   산출물(`degrade_final.json`)이었다. `degrade_final2.json` 의 R=0.843, F_h=0.494와
   F_e=0.085로 재계산해 **0.198→0.239, 292→96**, F_e 3배 민감도 77→**82**로 고쳤다.
2. **[critical] "tau=0.1에서 STT 호출 39.9% 절감"을 트래픽 가정 없이 단언**하고 있었다.
   39.9%는 p=0.05, q=0.30 가정에서만 나오고 논문 자신의 평가셋에서는 8.5%다. 초록과 결론에
   두 값을 함께 명시했다.
3. **[major] §6.2가 tab:vs를 인용하며 카드 재현율을 0.988로 적었다** — 그 표의 값은 1.000이고
   0.988은 gru_cnn의 값이다.
4. **[major] §5.6 마지막 문장이 "직렬 결합할 근거가 여기에 있다"로 캐스케이드를 무조건 권하여**
   신설 §6.2의 결론과 정면으로 어긋났다. §6.2로 넘기는 문장으로 바꿨다.
5. **[minor]** v2 train negative 626→**623**(이상치 제거 전 수치였다), "정밀도가 두 배 이상"→
   "hard-negative 오탐률이 절반 이하", 지연 단위 "클립당"→"5초 윈도당".
