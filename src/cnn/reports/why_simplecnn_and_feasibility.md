# 왜 simple_CNN이 더 좋았고, 왜 이 실험이 "가능성"을 입증했는가

> 음성 PII 탐지(STT 없이 멜 스펙트로그램 + CNN) 프로젝트의 분석 문서.
> 모든 수치는 실험 산출물(`runs/*.json`, `reports/results.md`, `progress/`) 근거.

---

## 1부 — 직접 설계한 simple_CNN이 대형 모델보다 좋은 이유

### 1.1 결과부터 (v1, controlled)


| Model              | F1              | ROC       | hard-neg FPR | Params  | 크기         | 추론(ms)   |
| ------------------ | --------------- | --------- | ------------ | ------- | ---------- | -------- |
| **simple_cnn** ⭐   | **0.955**       | **0.997** | **0.006**    | **60K** | **0.26MB** | **0.34** |
| efficientnet_b0    | 0.867           | 0.994     | 0.011        | 4.0M    | 16.3MB     | 2.92     |
| convnext_tiny      | 0.804 ±**0.13** | 0.962     | 0.056        | 27.8M   | 111MB      | 2.32     |
| mobilenet_v3_small | 0.776           | 0.945     | 0.021        | 1.5M    | 6.2MB      | 2.03     |


60K 파라미터 모델이 **460배 큰** ConvNeXt(28M)를 성능·안정성·속도 모두에서 능가했다.

### 1.2 왜? — 네 가지 이유

**(1) 데이터가 적다 → 큰 모델은 과적합**
학습 데이터가 ~2,000개뿐이다. ConvNeXt(28M)는 데이터당 파라미터가 과도해 패턴을 *외워버린다*.
근거: ConvNeXt만 시드 간 F1이 **±0.13**으로 흔들린 반면(데이터 적어 학습 불안정), simple_cnn은 ±0.01로 안정.
→ "큰 모델 = 좋음"이 아니라 "데이터가 충분할 때만 좋음". 소량에서는 오히려 독.

**(2) 도메인 불일치 → pretrained 이점 상실**
efficientnet/convnext/mobilenet은 **ImageNet(자연 사진)** 사전학습 모델이다.
멜 스펙트로그램은 사진이 아니라 "시간×주파수" 신호 이미지라, 사물 인식용 가중치가 거의 도움이 안 된다.
게다가 1채널 멜을 3채널로 복제해 넣어야 해 입력도 부자연스럽다.

**(3) 과제가 단순하다 → 깊은 추상화 불필요**
"PII 형식 숫자열이 들리는가"는 비교적 **저수준 음향 패턴**(자릿수 나열의 규칙적 리듬·억양)으로 풀린다.
멜 스펙트로그램에서 *규칙적 세로 줄무늬 텍스처*만 잡으면 되므로, 얕은 4블록 CNN으로 충분하다.

**(4) 작은 용량 = 자동 정규화**
표현력이 제한된 모델은 노이즈 대신 핵심 패턴만 학습하게 된다(암묵적 정규화).
프리필터 목적(경량·빠름·안정)에도 정확히 부합 — 60K/0.26MB/0.34ms.

### 1.3 한 줄

> **소량 데이터 + 도메인 불일치(사진≠스펙트로그램) + 단순 과제** 조합에서는 과제 크기에 맞춘 경량 전용 CNN이 대형 ImageNet 백본을 이긴다. (데이터가 수십만으로 커지고 과제가 복잡해지면 역전 가능 — 이 결론은 본 설정 한정.)

## 2부 — 왜 이 실험이 "가능성(feasibility)"을 입증할 수 있었는가

높은 정확도 수치 하나만으로는 "가능성 입증"이 안 된다. 모델이 **엉뚱한 단서(artifact)로 맞히는** 경우가 흔하기 때문이다. 이 프로젝트는 그 함정들을 **통제 실험으로 하나씩 차단**했기에 결론이 방어된다.

### 2.1 기준선(baseline)을 넘었다 — "학습했다"의 최소 조건


| 기준선                                                     | 무엇            | ROC       |
| ------------------------------------------------------- | ------------- | --------- |
| majority                                                | 다수 클래스만       | 0.50      |
| duration-only                                           | 길이 1개 feature | 0.70      |
| acoustic-LR                                             | 수작업 음향통계 7개   | 0.88      |
| **simple_cnn**                                          | 멜+CNN         | **0.997** |
| → 전역 음향 통계(acoustic-LR)로 안 잡히는 **시간-주파수 패턴**을 학습했다는 근거. |               |           |


### 2.2 artifact를 통제했다 — "형식을 본다", "길이로 속이지 않는다"

- **길이 단서 차단**: duration-only는 length-matched 평가셋에서 ROC 0.70→**0.53(우연)**으로 붕괴하지만, CNN은 length-matched F1이 controlled와 동일(0.956 vs 0.955). → 길이로 맞히는 게 아니다.
- **"숫자 존재"가 아니라 "형식"**: 날짜·주문번호·가격 등 *비PII 숫자열*(hard-negative)에 대한 FPR이 **0.006**. → 숫자가 들린다고 PII로 찍는 게 아니라 형식을 구분한다.
- **읽는 방식 통제**: positive와 hard-neg 모두 숫자를 *한국어 자릿수 발음*("공일공")으로 읽게 해, 클래스 차이가 '읽기 스타일'이 아니라 '숫자열 형식'이 되도록 했다.
- **출처 지문 통제**: 무음 대신 노이즈 패딩, 그리고 v2에서는 모든 클래스를 동일 화자·동일 TTS·동일 ffmpeg로 생성 → 코덱/화자 같은 출처 단서로 분류하지 못하게 했다.

### 2.3 일반화를 두 축으로 검증했다 — "외운 게 아니다"

- **화자 일반화(speaker-disjoint LOSO)**: 처음 보는 화자에 대해 F1 0.616(3화자)→**0.861(14화자)**, 분산 0.28→0.10. 화자를 외워 맞히는 게 아니라 신호를 일반화한다.
- **PII 유형 일반화(held-out-PII)**: 주민/카드/계좌를 각각 **학습에서 완전히 제외**하고도 recall **0.88~0.98**로 검출. 특정 패턴 암기가 아니라 "PII 형식"을 유형 너머로 일반화한다(가장 강한 증거).

### 2.4 평가 규율 — 누수 없는 측정

- 모든 실험 train/val/test 분리(70/15/15), **template-disjoint + length-stratified**, val은 early stopping 전용·test는 학습/선택에 미사용.
- LOSO·held-PII·viz 4샘플 검증은 test가 *학습에 없던* 화자/유형/클립이라 더 엄격. (viz 4샘플: 학습 제외 후 4/4 정답.)
- 3 seed 반복으로 안정성 확인.

### 2.5 왜 이것으로 충분한가

"가능성 입증"의 핵심 질문은 **"진짜 PII 신호를 학습했는가, 아니면 우연/artifact인가"**이다. 위 통제들은 각각:

- 기준선 초과 → 단순 통계 이상 학습함
- length-matched/hard-neg → 길이·숫자존재 artifact 아님
- LOSO/held-PII → 화자·유형을 외운 게 아니라 일반화함
- train/val/test 규율 → 측정 자체가 누수 없음

이 네 가지가 동시에 성립하므로, "STT 없이 음향만으로 PII 형식을 탐지할 수 있다"는 **feasibility 결론이 방어 가능**하다.

### 2.6 입증한 것 / 아직 아닌 것 (정직한 경계)

- **입증**: 합성 음성에서, STT 없이, artifact 비의존으로, 화자·PII유형을 일반화하여 PII 형식 숫자열을 **높은 recall로 선별** 가능.
- **미입증**: 실제 통화(잡음·억양) 성능, 운용 precision(현재 비PII 숫자열 과다검출 — hard-neg FPR이 v2에서 0.25~0.54로 약점), 문맥상 실제 민감성 판단. → 다음 과제: calibration·실데이터.

## 핵심 한 줄

> **모델 측**: 소량·도메인불일치·단순과제에는 경량 전용 CNN이 최적이라 60K simple_cnn이 28M 백본을 이겼다.
> **입증 측**: 기준선 초과 + artifact 통제(길이·숫자존재·읽기·출처) + 이중 일반화(화자·PII유형) + 누수 없는 평가 — 네 겹의 통제가 동시에 통과했기에 "STT 없는 음향 PII 탐지" 가능성이 방어 가능하게 입증됐다.
